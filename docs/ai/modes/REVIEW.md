# AI Mode — Review

## 목적

구현된 코드와 설계를 독립적으로 검토한다.

## AI의 역할

AI는 리뷰어 역할을 한다. 수정부터 하지 않고 문제를 먼저 찾는다.

## 권장 프롬프트

```text
[리뷰]

아래 코드/구조를 먼저 분석해줘.
바로 수정하지 말아줘.

다음 항목을 검토해줘.

1. ROS 2 구조상 문제
2. 코드 오류 가능성
3. 논리적 오류
4. 런타임 오류 가능성
5. Topic / Message / TF 문제
6. Node 간 충돌 가능성
7. 실제 LIMO에서 발생할 수 있는 문제
8. 유지보수성
9. 개선 가능한 부분

확실하게 확인되는 문제와 개선 제안을 구분해줘.

각 문제에 대해:
- 문제
- 근거
- 영향
- 개선 방법

순서로 설명해줘.
```

## 리뷰 원칙

- 실제 문제와 스타일 개선을 구분한다.
- 확인되지 않은 문제를 확정적으로 말하지 않는다.
- 현재 프로젝트 요구사항과 관련 없는 개선은 별도로 표시한다.
- 리뷰 결과를 바탕으로 수정 여부를 사용자가 판단한다.

## 완료 조건

발견된 문제와 개선사항을 이해하고 필요한 수정 항목을 결정할 수 있으면 구현/디버깅 단계로 돌아간다.
